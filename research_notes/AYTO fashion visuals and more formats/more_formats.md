# AYTO: further creative formats on the same engine (beyond film, reel, fashion)

Researched 28–29 Oct 2026. Three read-only probes were run against the hackathon host (`https://hackathon.api.qloo.com`) through the repo's own client (`src/qloo.js`), printing only counts and property key names; nothing was saved to the repo. Facts older than 2025 are marked. "[live probe, 28 Oct 2026]" marks a fact verified by those probes rather than by a public page.

## Which Qloo entity types carry years for a supply count, and which carry images for the background wall?

### Takeaway
Years: `movie` and `tv_show` carry `release_year` (number), `release_date` and `finale_year`; `book` carries `publication_year` (number) and `publication_date`; `podcast` and `videogame` carry only `release_date` (ISO string, so the year is `slice(0,4)`); `brand` has `founded_year`, `artist` has `start_year`, `person` has `date_of_birth`; `place` and `destination` carry no year at all. Images: 8/8 sample entities for book, podcast, place (`image` + `images`), brand, artist, person, movie; 7/8 tv_show; only 3/8 videogame; 0/8 destination (its only property is `geocode`).

### Cited Findings
- Year filters are documented only for Book (`filter.publication_year.min/max`), Movie (`filter.release_year.min/max`), TV Show (`filter.release_year`, `filter.latest_known_year`, `filter.finale_year`) and Person (`filter.date_of_birth`, `filter.date_of_death`); Artist, Brand, Destination, Place, Podcast and Video Game list no year filter — [Available parameters by entity type](https://docs.qloo.com/reference/available-parameters-by-entity-type)
- The `filter.type` enum is artist, book, brand, locality (partial), movie, person, place, podcast, tv_show, videogame, heatmap, plus the deprecated audience; the URN is `urn:entity:videogame` with no underscore. `filter.exists` can require `properties.image` or `properties.description` — [Insights API deep dive](https://docs.qloo.com/reference/insights-api-deep-dive)
- The onboarding example for a movie shows `properties.release_year`, `release_date`, `description`, `content_rating`, `duration`, `image.url`, `akas`, `filming_location`, `production_companies`, `release_country`, `short_descriptions` — [API onboarding](https://docs.qloo.com/reference/api-onboarding)
- Property keys returned by a raw Insights read (`filter.type=urn:entity:<type>`, `signal.location.query="Hyderabad, India"`, `take=8`) — [live probe, 28 Oct 2026]:
  - book: `publication_year` (number, 8/8), `publication_date` (7/8), `isbn10/13`, `page_count`, `publisher`, `series_name`, `language`, `format`, `image` (8/8); only 2/8 entities carried `tags`.
  - podcast: `release_date` (8/8, sample values 2024-07-05 … 2024-07-13, i.e. recent-episode-like dates), `episode_count`, `channel`, `rating`, `content_rating`, `image` (8/8); 8/8 carried tags.
  - videogame: `release_date` (8/8), `platforms`, `steam_tags`, `genre`, `gameplay_type`, `art_style`, `player_mode`, `camera_perspective`, `progression_type`, `skill_level`, `developer`, `publisher`, `universe`, `image` (3/8); 7/8 carried tags.
  - place: no year; `cuisine_description`, `specialty_dishes`, `menu_url`, `price_level`, `price_range`, `ambience_description`, `good_for`, `live_music`, `event_spaces`, `hours`, `neighborhood`, `business_rating`, `image` and `images` (8/8); 8/8 carried tags.
  - brand: `founded_year` (object), `products`, `price_range_usd_min/max`, `target_demographics_description`, `target_age_group`, `aesthetic_properties`, `competitor_brands`, `key_markets`, `image` (8/8).
  - artist: `start_year` (number), `date_of_birth`, `notable_songs`, `primary_genres`, `instruments`, `lyrical_themes`, `performance_style`, `image` (8/8).
  - person: `date_of_birth`, `notable_work`, `award_received`, `gender`, `image` (8/8).
  - destination: `geocode` only; 0/8 images.
  - movie and tv_show: `release_year`, `release_date`, `finale_year`, `genres`, `keywords`, `plot_summary`, `image` (8/8 and 7/8).
- The harness workflow tool `qloo_recommend` accepts `target_type` book, podcast, videogame, place and brand (5/5 results, `status=ok` each); typed tag reads (`filter.type=urn:tag`, `filter.parents.types=urn:entity:<type>`, `signal.location.query`) return 10 tags for each: book → `genre:qloo`, `theme:qloo`; podcast → `genre:qloo`, `genre:media`, `theme:qloo`; videogame → `genre:qloo`, `theme:qloo`, `character:qloo`, `emotional_tone:qloo`; place → `genre:place`, `ambience:qloo`; brand → `genre:brand`, `emotional_tone:qloo`, `cultural_relevance:qloo`, `aesthetic_property:qloo` — [live probe, 28 Oct 2026]
- In `qloo_recommend` results (top 20, two cities) a year/date field is present on movie, tv_show, podcast and videogame (20/20) but on 0/20 books, 0/20 artists, places, brands, persons; images on 20/20 for movie, artist, book, podcast, place, brand, 19/20 tv_show, 18–20/20 person, but only 8/20 (Hyderabad) and 4/20 (Las Vegas) for videogame; recommend results expose only 1–7 property keys per type, far fewer than the raw Insights read — [live probe, 28 Oct 2026]
- The repo counts supply as entities whose `properties.release_year >= thisYear − 4` inside the raw Insights catalogue read, matched to a flavour by tag id or stemmed tag name; `FORMATS[*].supply` lists the types that may be counted (`src/engine/gap.js`, `src/formats.js`). The read stage already labels `book`, `podcast` and `videogame` in its title map (`src/engine/read.js`), and `src/analysis.js` normalises `properties.image.url` into `row.image` for the wall.

### Inferences
- Supply becomes countable for book, podcast and videogame with one helper in `gap.js`: `yearOf = e => e.properties?.release_year ?? e.properties?.publication_year ?? Number(e.properties?.release_date?.slice(0, 4))`, plus adding the type to `FORMATS[id].supply`. For podcasts the `release_date` values looked like latest-episode dates, so "recent" should be read as "still publishing" (active supply), which is the right measure for a show anyway.
- Book supply by flavour will often read 0 because only 2/8 book entities carried tags; the gap stage's `exists` filter would then drop most lanes. A book format should either run demand-only (the UI already has the "Supply isn't readable for this format" note in `public/app.js`) or count supply with `filter.tags=<theme>` only and skip the per-flavour match.
- The place type is rich enough to ground a menu, an event night or a wedding brief without any year: `cuisine_description`, `specialty_dishes`, `price_level`, `live_music`, `event_spaces`, `good_for`, `ambience_description` are real Qloo fields. Supply for a food format can be counted as venues instead of titles: `filter.type=urn:entity:place` + `filter.tags=<cuisine or ambience tag>` + `filter.location.query=<city>` and count results.
- The brand type's `products`, `price_range_usd_*`, `target_demographics_description` and `aesthetic_properties` ground a retail assortment or merch line; the videogame type's `steam_tags`, `gameplay_type`, `art_style`, `player_mode`, `platforms` ground a game pitch on mechanics vocabulary. These rich fields come only from the raw Insights read, which the gap stage already performs for supply, so the digest (`src/writers/shared.js`) needs a small change to pass a few properties of the lane titles through.
- The wall works unchanged for podcast, book, place, brand, artist and person formats; a game format should mix movie/tv_show reference images into the wall because only 3–8 of 20 games carry one; a tourism format cannot use `destination` for the wall at all.

### Gaps
- Qloo publishes no per-type property reference: `docs.qloo.com/reference/entity-type-parameter-guide` and `/reference/entity-types` returned 404 on 28 Oct 2026; the key lists above come from an 8-entity sample per type for one city and may be incomplete.
- Whether podcast `release_date` is the show's first episode or its latest is not documented; the sampled values (all July 2024) suggest a snapshot of latest activity, not launch dates.
- Whether `filter.release_date.min` is honoured for podcast and videogame (the parameter exists globally but is not listed for those types) was not tested; the repo's approach of reading the catalogue and filtering locally sidesteps it.

## Which formats have the largest or most sympathetic maker populations in India and globally?

### Takeaway
By headcount the biggest pools are restaurants and cafés (NRAI says it represents about 5 lakh restaurants; Zomato averaged 3.06 lakh active partner restaurants in Q3 FY25), podcasters (over 200,000 podcasts created on Spotify in India in 2023 alone; 105 million Indian listeners in 2024), weddings and events (46 lakh weddings projected for the Nov–Dec 2025 season; 4,500 organised event companies; 34,086 ticketed live events in 2025), and writers (Pratilipi hosts over 15 million stories from roughly a million writers; about 3.5 million self-published ISBNs globally in 2025). Game studios are fewer (1,888 Indian gaming companies) but carry the clearest pain (19,008 Steam releases in 2025, nearly half with fewer than 10 reviews).

### Inferences
- The maker pools that match AYTO's existing lead persona (a small maker in one city who must choose what to make next) are podcasters, indie game studios, independent musicians and café or restaurant owners. Weddings and OOH are large in money but the "maker" is a planner or agency executing a client's brief, so the taste read is a sales aid rather than a creative decision.
- The clearest "pain" evidence is in games (half of 19,008 Steam releases under 10 reviews) and podcasts (82% of surveyed Indians unaware of podcasts in 2024; 200,000+ new Indian shows a year): both are discovery problems that a "loved here, under-served" lane speaks to directly.
- Restaurants are the largest Indian pool by far and the most local by nature, and Qloo's own flagship stories (Starbucks neighbourhood playlists, Michelin) sit in hospitality, which makes a café format easy for a judge to believe.

### Gaps
- No 2024–25 count of Indian podcast creators beyond Spotify's 2023 figure; no total Indian restaurant outlet census (the NRAI IFSR 2024 outlet count is not online; an undated older estimate of 1.5 million outlets exists at [IndiaRetailing](https://www.indiaretailing.com/?p=60206)); no reliable count of working stand-up comedians (a 500 figure is undated and pre-boom); no KDP India author count; no state-level tourism marketing budgets; no theatre or local-magazine maker counts. Wedding counts conflict (CAIT's 46 lakh covers a 45-day season; Ken's 8–10 million is annual).

## For which formats does "what this city loves that the country doesn't" clearly change the output?

### Takeaway
Measured live on two cities, the city's top-20 differs from the country's top-20 most for place (95% Hyderabad, 90% Las Vegas), tv_show (95%, 100%), person (85%, 100%), artist (90%, 85%), movie (80%, 100%) and videogame (80%, 95%), moderately for brand (70%, 100%) and book (60%, 90%), and least for podcast in India (25% Hyderabad, though 80% in Las Vegas). So food, events, music, film, people and game formats get a strong city column; a podcast format in India must carry its differentiation in the tag lift and the guest (person/artist) columns rather than the show list.

### Cited Findings
- City-vs-country set difference (`qloo_recommend`, `signal_location`, limit 20, onlyHere = city picks absent from the country list) — [live probe, 28 Oct 2026]:
  - Hyderabad vs India: movie 16/20, tv_show 19/20, artist 18/20, book 12/20, podcast 5/20, videogame 16/20, place 19/20, brand 14/20, person 17/20.
  - Las Vegas vs United States: movie 20/20, tv_show 20/20, artist 17/20, book 18/20, podcast 16/20, videogame 19/20, place 18/20, brand 20/20, person 20/20.
- Qloo's JCDecaux case study says its geospatial insights identify where taste for a brand is strong "from whole cities down to individual city blocks", and claims a 10x improvement in ad-targeting ROI for JCDecaux (vendor claim, audience of 800 million people a day) — [Qloo case study](https://qloo.com/blog/jcdecaux-case-study); the partnership began in 2020 and Qloo's taste data was integrated into JCDecaux's Displayce DMP in April 2025 — [MarTech Series](https://martechseries.com/predictive-ai/ai-platforms-machine-learning/qloo-and-jcdecaux-use-ai-powered-taste-data-to-deliver-hyper-localized-dooh-campaigns/).
- Qloo's recruiting boilerplate states "Starbucks is using Qloo to create in-store music playlists tailored to specific neighborhoods" — [Welcome to the Jungle job page](https://app.welcometothejungle.com/jobs/2YerO1Cd); Qloo's own company page names Netflix, Starbucks, JCDecaux and Michelin as clients without detail — [qloo.com/company](https://qloo.com/company).
- Michelin's use of Qloo began in 2018 via Tablet Hotels and extends "taste matching" to Michelin Guide restaurants — [TechTarget](https://www.techtarget.com/ai/news/366570853/Taste-intelligence-and-AI-vendor-raises-25-million); [CB Insights](https://www.cbinsights.com/company/qloo/customers).
- Regional music and audio taste in India: independent I-Pop made up half of Spotify India's 2025 top 10 and 90% of Top 50 India tracks were by Indian artists — [RouteNote](https://routenote.com/blog/spotify-indian-artists-loud-and-clear/); Spotify reported a Tamil podcast consumption surge in India — [Dinamalar](https://www.dinamalar.com/news/kalvimalar-news-en/-tamil-podcast-consumption-surges-on-spotify-in-india/51539).
- The repo's own verified facts: a tag used as a signal "gets swamped by the location" (crime + Hyderabad returned Borat), and affinity is flat at the top (0.98–1.00) so the engine ranks by set differences, not raw affinity — `CLAUDE.md`, `src/engine/read.js`.

### Inferences
- Strong city signal (the read alone changes the output): café menu and playlist, live event night, wedding theme, OOH, retail assortment, film and series, music single, game. Moderate: book. Weak in India: podcast show lists; a podcast format should lean on `person` (85–100% onlyHere) for guests and on podcast tag lift for the lane.
- Game taste is more global than film taste in content, but the measured city column still differs 80–95%, so the format can keep the three-column card; the lane (flavour tag lift with `filter.parents.types=urn:entity:videogame`) is where the local angle shows, and the rich properties ground mechanics.
- Tourism is the one format where the direction of the read is wrong: AYTO reads what a city's own crowd loves, while a tourism campaign needs which other cities' crowds lean to what this city has; that needs the `travels` heatmap inverted (signal = this city's places, read across the country), a new stage.

### Gaps
- Only two cities were measured; onlyHere can be inflated when Qloo returns near-duplicate entities, and the probe did not measure tag-lift magnitude per type, which is what the gap stage actually uses.

## What do existing AI "idea generator" tools produce for these formats, so AYTO's output is not just a prompt result?

### Takeaway
Every candidate format already has a prompt-wrapper generator (podcast episode ideas, game pitches, menu designs, book outlines, party themes, billboard layouts, venue playlists), and none of them reads a city's taste, shows evidence, counts supply or offers a with/without comparison; the closest demand-driven tools (Tastewise for menus, Soundtrack Your Brand's "location, vibe" prompt for playlists) use social or catalogue data, not city-over-country rank lift.

### Cited Findings
- Podcast: Talknotes generates six episode ideas from a show description using the OpenAI API, free, with CSV export — [Talknotes](https://talknotes.io/tools/idea-generator/podcast-ideas-generator); RightBlogger returns five on-topic ideas with tone presets — [RightBlogger](https://rightblogger.com/tool/podcast-episode); Alitu Showplanner produces a description, pitch and suggested format from a few questions — [BusinessCloud](https://businesscloud.co.uk/news/new-ai-tool-generates-podcast-launch-kit-in-a-minute/).
