# Turning a written fashion drop into outfit visuals (as of 29 Oct 2026)

Scope: AYTO already writes a drop as JSON — `styles[]` with `name`, `category`, `cues` (silhouette, material, print, detail), `from_tags`, `colourways`, `hero`, and a `palette[]` of `{name, hex, from_tags}` (`src/writers/fashion.js`). The front end draws palette chips and style cards (`public/app.js` ~line 1000) and the share page draws swatches (`src/pipeline/page.js`). The question is whether, and how, to turn that JSON into pictures in a two-day build that must work with a user-supplied key.

Pricing figures below are list prices read on 28–29 Oct 2026 unless marked older. "Third-party" means an aggregator or reseller page, not the vendor.

## Key question 1 — Which text-to-image APIs work bring-your-own-key, and what do they cost, how fast are they, and what do garment renders look like?

### Takeaway
Every major image API except Midjourney is a single REST call with an API key. The cheapest credible garment renders are FLUX.2 [pro] at $0.03 per 1 MP image and Google's Nano Banana 2.1 at $0.034 per 1K image; OpenAI's GPT Image 2 / 2.5 score highest on quality but cost $0.053 (medium) to $0.21 (high) per image and can take up to two minutes. OpenAI retired `gpt-image-1` on 23 Oct 2026, so any code that names it is already broken.

### Inferences
- For a BYOK app, the two keys most users already hold are OpenAI and Google. Supporting `gpt-image-2.5-flare` (fast tier) and `gemini-nano-banana-2.1` covers both; adding FLUX.2 [pro] through fal or BFL adds the cheapest high-volume option and the only documented hex-colour prompting.
- Per-drop cost at five styles, one 1K image each: FLUX.2 [pro] $0.15; Nano Banana 2.1 $0.17; GPT Image 2 medium $0.27; Nano Banana Pro $0.67; GPT Image 2 high $1.06. All are cheaper than the LLM call is likely to be irrelevant to; none breaks a hackathon budget, but the public demo risk (Key question 5) is about uncontrolled volume, not unit price.
- Latency for five sequential renders: Nano Banana 2.1 roughly 1–1.5 minutes (inferred from the 15.5 s NB2 measurement), GPT Image 2 potentially several minutes at high quality, FLUX.2 [klein] under 10 s total. Rendering must be parallel and streamed, or precomputed.
- Garment credibility (inference from arena rankings and model docs, not a fashion-specific benchmark): GPT Image 2/2.5 and Nano Banana Pro lead on prompt adherence and text, which matters for graphic-print tees; FLUX.2 is the only family that documents exact hex-colour control, which matches AYTO's palette JSON directly. Flat-lay "ghost" product shots are the lowest-risk prompt type because they avoid faces, bodies and skin tone entirely.
- Prompt recipe that maps AYTO's JSON onto these models (inference, built from the BFL hex guide and OpenAI structured-prompt guidance): one style per call; "flat-lay product photo, white seamless background, top-down, soft studio light"; then `category` + each `cue` as a clause; then "the garment body in color #RRGGBB, the rib trim in color #RRGGBB" tying each hex to a surface; end with "no logos, no text, no mannequin, no person". Fix `seed` where the API offers it (FLUX, Ideogram, Recraft) for repeatable colourway variants.
- Recraft's vector endpoint ($0.08) is the only API that can return an SVG, which would give a line-art "croquis" look that is editable and tiny; untested for garments.

### Gaps
- No fashion-specific quality benchmark exists for any of these models; "credible garment render" is an inference from general arena scores and vendor feature docs.
- The Ideogram and Stability pricing pages could not be fetched directly (connection resets); figures come from search excerpts of those official pages.
- The OpenAI guide's portrait (1024×1536) column for GPT Image 2 read as cheaper than square ($0.041 vs $0.053 medium), which looks like an extraction artefact; verify in the guide's calculator before quoting.
- Whether Together's serverless `/v1/images/generations` is OpenAI-SDK compatible without dedicated containers was not confirmed.
- Current Midjourney status is known only from third-party sources; no official statement either way.

## Key question 2 — Virtual try-on and "dressing simulator" options: which have APIs, what do they need, and is any realistic in two days?

### Takeaway
Three try-on services are one REST call each and allow commercial use: FASHN ($0.075 per image, 7–19 s), Kling Kolors v1.5 via fal ($0.07) and Google Vertex Virtual Try-On ($0.06, GA since Jan 2026). All need a photo of a real person plus a garment photo, so they only help after a garment image exists. The research models (IDM-VTON, OOTDiffusion, CatVTON) are CC BY-NC-SA and cannot be used in a product; the 3D tools (CLO3D, Browzwear, Marvelous Designer, Style3D) are desktop or enterprise integrations with no two-day path.

### Inferences
- A "dressing simulator" is the wrong feature for AYTO: every try-on API consumes a garment image and a person image, so it is a second hop after a garment render, and it adds faces, bodies, skin tone and consent to the risk surface for no gain in the judges' test (Qloo depth, completeness, real problem, non-obvious). The garment render is the thing to show; try-on is a "later" tier.
- If try-on is added later, FASHN v1.6 is the only one with published mode-by-mode latency, documented flat-lay garment input and a plain API-key sign-up; Kling via fal is the same price; Vertex is the cheapest but needs a Google Cloud project, billing and OAuth/service-account auth rather than a single key (inference from Vertex being a GCP product, not stated on the page).
- The person image should be a stock or synthetic mannequin photo chosen by the app, never a judge's or user's photo, to avoid storing faces.
- 3D garment tools are out of scope for any hackathon tier; they are desktop CAD with enterprise-only automation.

### Gaps
- Kling's official API doc and unit pricing could not be read (JS-rendered page); fal/Eachlabs prices are reseller prices.

- No independent latency figure for Kling or Vertex try-on.
- Vue.ai and Style3D API status is unverified in either direction.

## Key question 3 — Alternatives that need no image model

### Takeaway
AYTO already has the raw material for a convincing no-model visual: Qloo entity images are already read into the run (`properties.image.url`) and tiled by `src/mosaic.js`, and the drop JSON already carries hex colours and silhouette cues. A drawn SVG croquis per style plus a mood-board strip of the city's own Qloo brands/artists is a few hours of work and reads as design, not as stock AI art.

### Cited Findings
- The repo reads `r.properties?.image?.url ?? r.properties?.image` for every resolved entity and for catalogue/brand rows — `src/engine/resolve.js` line 112, `src/analysis.js` lines 274 and 318 (local code, this worktree)
- `src/mosaic.js` already builds a wall of Qloo-hosted images from a run's read columns and audio shortlist, filtered by Qloo popularity thresholds per type (movie 0.9, artist 0.75, brand 0.85 …), capped at eight per type, woven with curated Unsplash fashion editorial shots from `public/mosaic-curated.json`; "Qloo hosts the images; nothing is copied into the repo" — `src/mosaic.js` (local code)
- The fashion writer's schema: `styles[] {name, category, cues[], from_tags[], colourways[], hero}` and `palette[] {name, hex, from_tags[]}`; "3-5 styles with 1-2 hero, 3-5 palette colours" — `src/writers/fashion.js` lines 11–18 (local code)
- Palette chips and style cards are already rendered in `public/app.js` (~line 1000) and in the share page `src/pipeline/page.js` line 39–40, with a hex sanitiser that falls back to a default colour (local code)
- Recraft's API can return vector output (V4 vector 80 units = $0.08; V4.1 Utility vector 80 units) — [Recraft API pricing](https://www.recraft.ai/docs/api-reference/pricing)
- Heuritech's forecasting product presents trends as colour/print/fabric signals feeding a "Trend Radar", and earlier shipped a Pantone-linked moodboard platform — [Apparel Resources on Heuritech–Pantone](https://apparelresources.com/technology-news/retail-tech/heuritech-pantone-collaborate-provide-latest-colours/) (older announcement); [FashionUnited on Heuritech](https://fashionunited.uk/news/fashion/heuritech-launches-trend-forecasting-platform/2020120252302)

### Inferences
- Effort ranking for the two-day build (inference): (a) CSS swatch cards already exist, 0 h; (b) a mood-board strip reusing `mosaicFor(run)` filtered to brand + artist tiles next to the drop, about 1–2 h; (c) an SVG croquis per style, about 3–5 h: a fixed set of garment outlines keyed by `category` (tee, oversized tee, hoodie, shorts, dress, kids set — the categories the Tiruppur showcase produces), filled with `palette[].hex`, with a print-pattern layer (stripe, graphic block, all-over dots) chosen from `cues`/`from_tags`, and the colourway names as a row of mini-swatches; (d) a one-page "line sheet" PDF/HTML combining (b) and (c) for the share page, 1–2 h.
- How convincing to a judge: the SVG croquis is honest (it is a spec drawing, which is what a garment maker sends to a factory) and cannot "hallucinate" a seam; its weakness is that it looks schematic next to a photoreal render. The mood board is strong on "uses Qloo deeply" because every tile is a Qloo entity with a receipt, which no image model can claim.
- The croquis and the render are complementary: render the hero style(s) with an image model when a key is present, draw every style as a croquis always. Then a missing or failing image key degrades to the croquis instead of an empty card.

### Gaps
- No source measures how judges or buyers rate schematic croquis versus AI renders; this is design judgement.
- Qloo's documentation of the `properties.image` field was not located in search; the field's presence is confirmed only by the repo's working code.

## Key question 5 — Risks: refusals, bias, logos, cost blow-up, slow renders, and how to cache

### Takeaway
Flat-lay garment renders avoid the three biggest risks at once (face refusals, skin-tone bias, consent), hex-anchored prompts plus "no logos, no text" avoid brand marks, and precomputing the three showcases at boot with a hashed file cache removes live-render latency from the judge session.

### Cited Findings
- OpenAI: blocked requests return `moderation_blocked` with `moderation_details.categories` and `moderation_stage` (input or output); `moderation: "low"` is "less restrictive"; "All prompts and generated images are filtered in accordance with our content policy" — [OpenAI image generation guide](https://developers.openai.com/api/docs/guides/image-generation). Developers report over-refusals on gpt-image-2 via API even with `moderation: low` where ChatGPT succeeds — [OpenAI community thread](https://community.openai.com/t/api-issue-moderation-over-refusals-on-gpt-image-2-with-moderation-low-where-chatgpt-always-succeeds/1388964) (anecdotal)
- Google: "All generated images include a SynthID watermark"; users must hold rights to uploaded images and must not create deceptive or harmful content — [Gemini image generation guide](https://ai.google.dev/gemini-api/docs/image-generation). Vertex try-on supports configurable "person generation" safety settings and C2PA Content Credentials — [Vertex Virtual Try-On docs](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/imagen/virtual-try-on-preview-08-04?hl=en)
- Skin-tone bias (older, 2023): Bloomberg's analysis of more than 5,000 Stable Diffusion images found high-paying job prompts "dominated by subjects with lighter skin tones" and more than 80% of "inmate" images in the three darkest skin-tone categories — [Marketplace on the Bloomberg analysis](https://www.marketplace.org/shows/marketplace-tech/is-ai-more-biased-than-humans/); [DeepLearning.AI summary](https://www.deeplearning.ai/the-batch/stable-diffusion-may-amplify-biases-in-its-training-data)
- Reputational precedent (older, March 2023): Levi's use of Lalaland.ai models to "increase diversity" drew backlash ("lazy", "digital Blackface"); Levi's said AI "is not a means to advance diversity" — [Silicon Canals](https://siliconcanals.com/levi-strauss-lalaland-ai-models-backlash/); [PetaPixel](https://petapixel.com/2023/03/29/levis-use-of-ai-to-increase-diversity-is-wildly-tone-deaf)
- Colour control: BFL recommends tying every hex code to a named surface; unplaced codes "may produce inconsistent results" — [BFL hex colour guide](https://docs.bfl.ai/guides/usecases_t2i_hex_color_prompting)
- Latency bounds: OpenAI "up to 2 minutes" for complex prompts — [OpenAI image generation guide](https://developers.openai.com/api/docs/guides/image-generation); Nano Banana 2 ~15.5 s, Pro ~30.8 s — [Magic Hour](https://magichour.ai/blog/nano-banana-2-vs-nano-banana-pro-we-benchmarked-both-on-the-same-5-prompts); FLUX.2 [klein] "sub-second" — [FLUX.2 overview](https://docs.bfl.ai/flux_2/flux2_overview); FASHN 7/10/19 s — [FASHN v1.6 post](https://fashn.ai/blog/fashn-v1-6-our-best-virtual-try-on-model-yet-now-at-864-x-1296-resolution); IDM-VTON ~18 s — [Replicate](https://replicate.com/cuuupid/idm-vton)
- Licensing of research try-on models (CC BY-NC-SA, dataset NC terms, cease-and-desist example) — [FASHN developer guide](https://fashn.ai/blog/so-you-want-to-build-a-virtual-try-on-app-a-developers-guide-to-not-getting)
- Local constraints that shape caching: file cache in `.cache/` (git-ignored), `PREWARM=1` runs the three showcases at boot, user keys live in memory for one run only and never reach a run file or log — CLAUDE.md in this worktree

### Inferences
- Refusals: prompts for flat-lay garments with no people almost never trip image moderation; the cases that will are graphic-print tees whose print text or motif the LLM invents (slogans, real band names from Qloo artist reads, real brand marks from Qloo brand reads). Strip entity names from the image prompt even though they are in the written drop, and add "no logos, no brand marks, no readable text" to every prompt; if a model returns `moderation_blocked`, fall back to the croquis for that card rather than retrying.
- Logos: Qloo brand entities are the most likely source of accidental trademark renders ("in the style of X" prompts). Use brands only as mood-board tiles (Qloo-hosted images with receipts), never inside an image prompt.
- Bias: no on-model renders in the two-day build removes the skin-tone question entirely; if try-on is added later, let the user pick the mannequin photo from a fixed set spanning skin tones and body sizes and show which was used.
- Cost blow-up: BYOK means the visitor pays for their own renders, but the hosted showcases run on the project's key. Cap at one render per hero style (1–2 per drop), cache by `sha256(provider|model|style JSON)` in `.cache/`, serve showcase images from that cache, and never render on the share page. Worst case for a public demo: a stranger pastes their own key and spends their own money, which is acceptable; the project key must only ever render the three precomputed showcases.
- Slow renders in the judge session: precompute the showcases at boot (`PREWARM=1`), stream image URLs over the existing SSE channel as each completes, and always paint the croquis first so a card is never empty. Prefer `gpt-image-2.5-flare` low/medium or `gemini-nano-banana-2.1` 1K for live runs; reserve high quality for the cached hero.
- Watermark disclosure: Gemini images carry SynthID and Vertex adds C2PA; label rendered cards "AI render" in the UI so the receipts story stays honest.

### Gaps
- OpenAI's usage-policy page returned 403; no primary statement on trademarks/logos or real-person likeness in image outputs was captured. The March 2025 relaxation on public figures is known only from secondary coverage — [CO/AI](https://getcoai.com/news/chatgpts-image-generator-now-creates-public-figures-and-controversial-content)
- No measured refusal rate for garment prompts on any model.
- No 2025–2026 study of skin-tone bias specific to fashion image models was found; the Bloomberg analysis is from 2023 and about Stable Diffusion.

## Key question 6 — Recommendation: two-day build, and a later tier

### Takeaway
Show the outfits, but do not build a dressing simulator. Day 1: an SVG croquis per style driven by the existing JSON plus a Qloo mood-board strip, so every drop is visual with no image key. Day 2: an optional hero render through the user's own OpenAI or Google key (one call per hero style, cached, streamed), with FLUX.2 [pro] via fal as the cheap third provider if time allows. Try-on (FASHN or Vertex) and tech-pack export are the "later" tier.

### Cited Findings
- All supporting facts are cited in Key questions 1–5 above; the per-image prices used here are GPT Image 2 medium $0.053 — [OpenAI image guide](https://developers.openai.com/api/docs/guides/image-generation); Nano Banana 2.1 1K $0.0336 — [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing); FLUX.2 [pro] $0.03 — [fal FLUX.2 pro](https://fal.ai/models/fal-ai/flux-2-pro); FASHN $0.075 — [FASHN pricing update](https://fashn.ai/blog/pricing-update-for-developer-api); Vertex try-on $0.06 — [Vertex pricing (search excerpt)](https://cloud.google.com/vertex-ai/generative-ai/pricing)

### Inferences
- **Two-day build (ship order):**
  1. Croquis (always on): `src/croquis.js` with 6–8 garment outlines keyed by `category` (tee, oversized tee, polo, hoodie, shorts, dress, kids set, cap), filled from `palette[].hex`, a print layer from `cues`/`from_tags` (stripe, placement graphic, all-over), colourway mini-swatches, and the `from_tags` chips underneath. Render inline in `public/app.js` cards and in `src/pipeline/page.js`. No key, no latency, no refusals.
  2. Mood-board strip: reuse `mosaicFor(run)` limited to brand and artist tiles for the city, labelled "what {city} already loves", next to the drop. Pure Qloo evidence.
  3. Hero render (optional, BYOK): add an `image` provider slot in `src/keys.js`/`src/llm.js` for OpenAI (`gpt-image-2.5-flare`, quality low or medium, 1024×1024, JPEG) and Google (`gemini-nano-banana-2.1`, 1K); fal FLUX.2 [pro] third if time allows. One call per `hero: true` style, prompt built from category + cues + hex-anchored colours + "flat-lay, white background, no logos, no text, no person". Cache by hash in `.cache/`, stream the URL over SSE, mark the card "AI render". Precompute the three showcases at boot.
  4. Do not build: try-on, on-model renders, 3D, Midjourney.
- **Later tier:** (a) FASHN v1.6 or Vertex `virtual-try-on-001` on a fixed mannequin set, fed the hero render as the garment image; (b) Recraft vector output as a cleaner croquis; (c) a one-page tech-pack PDF (flat + swatches + spec + Qloo receipts) aimed at the Tiruppur sampling room; (d) multi-view (front/back) renders using FLUX.2 reference images for consistency.
- The with/without-Qloo card is unaffected: the croquis and render are downstream of the written drop, and the mood-board tiles are themselves Qloo receipts.

### Gaps
- Nothing here has been prototyped; the latency and refusal behaviour of flat-lay garment prompts on `gpt-image-2.5-flare` and `gemini-nano-banana-2.1` should be checked with one real key before committing to the hero render path.
